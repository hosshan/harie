# ADR-0006: 保存ファイル名の規則

- ステータス: 承認
- 日付: 2026-10-07
- 決定者: Shun（2026-10-07 承認）
- 関連: 要求 R3 / FR-FILE-06 / [ADR-0004](./0004-image-container-format.md)

## 背景

要求時のファイル名イメージは `example.{anoi:サービス名}.jpeg`。ここから読み取れる意図は次の 2 つ。

1. ファイル名を見ただけで Anoi ファイル（再編集できる画像）だとわかる。
2. どのサービスのガイド画像かがわかる。

一方で、文字どおりの表記には問題がある。

- `:` は Windows のファイル名に使えない。
- `{}` は URL・シェル・一部の CMS で扱いにくい。
- 日本語のサービス名は URL エンコードされ、CMS や Git で扱いづらいことがある。

なお、Anoi ファイルかどうかの判定は**ファイル名ではなく埋め込みデータ**で行う（ADR-0004）。ファイル名は人間向けのヒントであり、名前を変えても再編集はできる。

## 選択肢

### A. `<名前>.<サービス>.anoi.jpg`（例: `notification-settings.rimo.anoi.jpg`）

- 長所: 末尾が `.anoi.jpg` で統一され、検索・ファイル関連付け・一覧が簡単。サービス名も入る。
- 短所: 名前が長くなる。

### B. `<名前>.anoi-<サービス>.jpg`（例: `notification-settings.anoi-rimo.jpg`）

- 長所: 元のイメージ `{anoi:サービス名}` に最も近い。
- 短所: 末尾が一定でないため、拡張子ベースの関連付けや一覧の判定がしにくい。

### C. `<名前>.anoi.jpg`（サービス名なし）

- 長所: 最も短く単純。
- 短所: サービス名がわからない（フォルダ構成で代替）。

## 決定

**C. `<名前>.anoi.jpg` を採用する**（例: `notification-settings.anoi.jpg`）。

- サービス名はファイル名に入れず、フォルダ構成（例: `guides/rimo/`）で分ける。どのサービスの画像かは注釈ドキュメントの `meta.service` にも記録する。
- 使用可能文字は `a-z 0-9 -`。日本語名や記号は保存時にスラッグ化する（英数字の入力を促し、なければ日時ベース）。
- 拡張子は `.jpg` / `.png`（`.jpeg` も読み込みは可）。

検討時の推奨は A だったが、最も短く単純な C をユーザーが選んだ（2026-10-07）。

## 結果（影響）

- 良くなること: OS・URL・Git で安全に扱える。`*.anoi.*` で一括検索できる（MCP の `anoi_list` も既定でこのパターンを優先）。
- 受け入れるコスト: 元のイメージより表記が変わる。ファイル名だけではサービスが判別できないため、フォルダ構成か `meta.service` で補う。
