# ADR-0007: PII 加工はベース画像に不可逆に適用する

- ステータス: 承認
- 日付: 2026-10-07
- 決定者: Shun（2026-10-07 PR #1 のマージで承認）
- 関連: FR-PII-01〜05 / NFR-SEC-02 / [ADR-0004](./0004-image-container-format.md) / [注釈ドキュメントモデル](../03-design/document-model.md)

## 背景

Anoi ファイルは再編集のためにベース画像（注釈を焼き込む前の画像）を埋め込む（ADR-0004）。もし個人情報のマスクを「枠や矢印と同じ注釈」として可逆に持つと、**見た目はマスクされていても、埋め込まれたベース画像を取り出せば元の個人情報が読める**。ガイド画像は社外に公開されるため、これは重大な情報漏えいにつながる。

## 選択肢

### A. マスクを注釈として持つ（可逆）

- 長所: 後からマスク範囲を変えられる。
- 短所: ベース画像に元の情報が残る。公開ファイルから復元可能。

### B. マスクをベース画像に焼き込む（不可逆）。記録だけ残す

- 長所: ファイルのどこにも元の情報が残らない。
- 短所: マスクをやり直すには元のキャプチャが必要。

### C. 元画像を暗号化して埋め込み、可逆にする

- 長所: 権限のある人だけがやり直せる。
- 短所: 鍵管理が必要。暗号文でも公開ファイルに個人情報が含まれる状態は避けたい。

## 決定

**B を採用する。**

- PII 加工（ダミー置換・ぼかし・モザイク・塗りつぶし）は、ベース画像のピクセルを書き換えて新しいベース画像にする。加工前のベース画像はファイルにもメモリにも残さない。
- ドキュメントには加工の記録（種別・方法・範囲）だけを残す。元の値は残さない。
- ぼかし・モザイクは、復元攻撃に耐えるよう十分な強度（ブロックサイズ・半径の下限）を設ける。文字の場合は既定を「ダミー置換」または「塗りつぶし」とする。
- PII 以外の「見せたくないだけ」の領域向けに、可逆な `blur` 注釈も用意するが、UI 上で PII 加工と明確に区別し、PII 検出結果からは可逆マスクを選べないようにする。
- 「加工前の情報が残らないこと」を自動テストで保証する（NFR-SEC-02）: 加工後ファイルの全ペイロードを走査し、元のテキスト・元のピクセル領域が含まれないことを確認する。

## 結果（影響）

- 良くなること: 公開しても安全なファイルが既定になる。
- 受け入れるコスト: マスクの範囲を後から広げることはできるが、狭める・解除することはできない。やり直しには再キャプチャが必要。
- 後でやること: C2PA で「PII 加工済み」の来歴を付けられるか検証する。
