# ADR-0013: 日本語以外の文字のフォントを、注釈に現れたときだけ読み込んで描画に加える

- ステータス: 承認
- 日付: 2026-11-02
- 決定者: Shun（2026-11-02 に対応言語を 5 言語に広げると決定。この ADR を含む PR のマージで承認）
- 関連: NFR-I18N-01 / NFR-PLAT-05 / [ADR-0005](./0005-rendering-pipeline.md)

## 背景

UI の対応言語を日本語・英語から広げる（韓国語・繁體中文・简体中文など）。UI を訳すと、利用者はその言語で注釈を書く。

いまの描画（ADR-0005）は resvg に Noto Sans JP（400 / 700）だけを渡している。同梱の TTF の文字表を fontTools で調べると、ハングルは収録がなく、簡体字は試した 26 字のうち 13 字が欠けていた。タイ文字・デーヴァナーガリー・アラビア文字、トルコ語・ポーランド語の一部のラテン文字も欠けている。繁體字・ベトナム語・スペイン語・ポルトガル語・ドイツ語・フランス語・ロシア語は、試した範囲では欠けがなかった。

欠けた文字は保存画像で □（豆腐）になる。resvg で「設定 한국어 简体」を描くと、いまはハングルと「简」が □ になり、Noto Sans KR を `fontBuffers` に足すとハングルが正しく描かれた。resvg は欠けた文字を渡された別のフォントで補うので、SVG の `font-family` や保存形式を変える必要はない。

一方、Noto Sans KR は 1 太さ 6.2 MB、Noto Sans SC は 1 太さ 10.6 MB ある。全員に常に読み込ませると、Web の初回表示と Chrome 拡張のパッケージが重くなる。

また resvg の代替フォント選びは太さを見ない。補助フォントの Regular と Bold を両方渡しても、太字の注釈のハングルが Regular で描かれた（実測）。

## 選択肢

### A. 文字の種類ごとにフォントを分け、注釈に現れたときだけ読み込む

- 長所: 日本語・英語だけの利用者の読み込み量は変わらない。描画は `packages/render` の 1 系統のまま。
- 短所: 描画の前に「どの文字の種類が要るか」を判定して読み込みを待つ処理が増える。初めてハングルを打った瞬間に数 MB の読み込みが走る。

### B. すべてのフォントを常に読み込む

- 長所: 実装が最も簡単。
- 短所: Web の初回読み込みが 30 MB 以上増える。日本語・英語だけの利用者にも負担がかかる。

### C. サブセット化した 1 つのフォントに統合する

- 長所: 1 ファイルで済む。
- 短所: CJK を合わせるとサブセットでも大きく、文字を絞ると利用者が書く任意の文字に対応できない（NFR-I18N-01 の「任意の Unicode」に反する）。

## 決定

**A を採用する。**

- 補助フォントは、Noto Sans KR からハングルだけ、Noto Sans SC から Noto Sans JP にない文字（CJK の記号・統合漢字・全角形のうち 8,229 字）だけを取り出したサブセットにする（Regular / Bold で計 11 MB）。`packages/render/scripts/subset-fonts.py` で作り、`packages/render/fonts/` にコミットする。
- `packages/render` に、文字ごとに要る補助フォントを判定する純粋関数（`extraFontOf` / `requiredExtraFonts`）を置く。簡体字は、補助フォントが持つ文字の一覧（ビット列、`src/extra-font-coverage.ts`、生成物）で判定する。
- SVG では、補助フォントの文字の範囲を `<tspan font-family="Noto Sans KR">` などで囲む。resvg の代替選びに頼らず、ファミリーを明示して太さを正しく選ばせる。日本語・英語だけの注釈の SVG は変わらない。
- Renderer は `render` / `applyMasks` の前に、SVG に要る補助フォントを呼び出し側のローダー（`loadExtraFont`）で読み込む。フォントのバイト列の取得は環境ごとの呼び出し側が行い、render は DOM・Node に依存しない。
- Web・拡張・デスクトップは補助フォントを別ファイルとして同梱し、必要になったときに読み込む。CDN は使わない（オフラインでも動くため）。PWA は先回りしてキャッシュせず、初めて読み込んだときにキャッシュする。編集画面の表示用には同じファミリー名で `FontFace` を登録し、ブラウザが使うときに読み込む。
- MCP・CLI（Node）は、同梱した補助フォントを必要なときに読む。
- 漢字の字形の地域差（繁體中文を Noto Sans JP の字形で描くなど）は、この ADR では扱わない。

## 結果（影響）

- 良くなること: 韓国語・簡体字などの注釈が保存画像で正しく描かれる。日本語・英語だけの利用者の読み込み量は変わらない。
- 受け入れるコスト: Chrome 拡張・デスクトップ・@harie/mcp の配布物が 11 MB 大きくなる。リポジトリにフォントのバイナリ（11 MB）が入る。
- 再評価の条件: 配布物の大きさが問題になったら、太さを 400 だけにする、Web では初回だけ harie.studio から取得する、などを検討する。
