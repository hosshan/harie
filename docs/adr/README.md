# ADR（Architecture Decision Records）

アーキテクチャや開発方針に関する**重要な判断とその理由**を 1 件 1 ファイルで残す。コードやドキュメントは「今どうなっているか」しか語らないので、「なぜそうしたか」「何を捨てたか」はここに残す。人間にとっても、後から参加する AI エージェントにとっても、判断の経緯を再調査せずに済むようにするのが目的。

## 運用ルール

- **書くタイミング**: 後から変えるのが高くつく判断（技術選定、ファイル形式、データの持ち方、セキュリティ方針、開発プロセス）をするとき。迷ったら書く。
- **番号**: 4 桁の連番。欠番は作らない。ファイル名は `NNNN-kebab-case-title.md`。
- **テンプレート**: [`template.md`](./template.md) をコピーして使う。
- **ステータス**: `提案中` → `承認` / `却下`。承認後に覆すときは、新しい ADR を書いて旧 ADR を `廃止（ADR-XXXX により置換）` にする。
- **承認済み ADR の本文は書き換えない**（誤字・リンク修正は可）。判断が変わったら新しい ADR を書く。これが判断の履歴になる。
- **PR との関係**: ADR は PR で追加する。PR のマージをもって `承認` とする。マージ前にステータスを `承認` に更新すること。
- **AI エージェント**: 判断を伴う変更をするとき、関連 ADR を読み、矛盾する実装をしない。矛盾が必要なら実装ではなく新しい ADR を提案する。
