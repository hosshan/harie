# LP の訴求整理

- ステータス: ドラフト
- 最終更新: 2026-10-21
- 関連: [要求整理](../01-requirements/requirements-analysis.md)、LP の実装は [apps/site](../../apps/site/README.md)

GitHub Pages で公開する LP のために、近いツールの訴求を調べ、Harie が言えることを整理し直した記録。

## 1. 参考にしたツールと訴求

公開ページ・比較記事（2026-10 時点）から、見出しと主な主張を拾った。

| 種類 | ツール | 主な訴求 | 編集データの持ち方 |
|---|---|---|---|
| キャプチャ＋注釈 | Snagit | 1 本で撮る・描く・共有。手順書テンプレート、Step Capture、Smart Redact（機密の自動検出）、UI の簡略化 | 独自形式のプロジェクトで再編集。書き出した画像は焼き込み |
| キャプチャ＋注釈 | CleanShot X | 「1 本で複数ツールを置き換える」、14 種以上の注釈（番号・スポットライト・モザイク）、共有リンク | 独自形式で非破壊編集。書き出すと焼き込み |
| キャプチャ＋注釈 | Shottr | 速さ（撮影 17ms）、軽さ、安さ、OCR、16 種の注釈 | 画像に焼き込み |
| 手順書の自動生成 | Scribe | 操作を記録するだけで手順書ができる。Smart Blur で機密を自動でぼかす。AI で文書化 | 手順書はサービス上。画像単体の再編集は前提にしない |
| 手順書の自動生成 | Tango | 「数分で最初のガイド」、機密の自動ぼかし、アプリ内ガイド、定着の計測 | 同上 |
| 国内のマニュアル作成 | Dojo、Teachme Biz など | 作成工数の削減、現場で更新できる、属人化の防止（誰が作っても同じ品質） | マニュアルはサービス上 |

出典: [TechSmith の比較記事](https://www.techsmith.com/blog/cleanshot-alternative/)、[CleanShot X の紹介](https://thegtmdirectory.com/tools/cleanshot-x/md)、[Shottr のレビュー](https://www.bitdoze.com/shottr-mac-screenshot-tool/)、[Scribe の Image Blur](https://scribe.com/tools/image-blur-redaction)、[Tango vs Scribe](https://www.tango.ai/compare/tango-vs-scribe)、[マニュアル作成ツール比較（国内）](https://saas.imitsu.jp/cate-manual-preparation/article/l-2604)。

### 共通して使われている訴求

1. **時間が減る**（「数分で」「記録するだけで」）
2. **見栄えがそろう**（テンプレート、番号、誰が作っても同じ品質）
3. **機密を隠せる**（自動検出、自動ぼかし）
4. **1 本で済む**（撮影から共有まで）

### どこも言っていないこと

- 書き出した画像そのものを後から直せる。各ツールの再編集は独自形式のプロジェクトファイルかサービス上のデータが前提で、ヘルプページに貼った JPEG/PNG は焼き込みになる。
- 作った人以外が直せる。プロジェクトファイルは作成者の手元に残り、手順書 SaaS はアカウントと契約が要る。
- AI エージェントが画像の注釈を直接読み書きできる。
- ぼかすのではなく、ダミーに置き換えて「何の画面か」は伝わるまま隠す。

## 2. Harie の訴求（見直し後）

要求整理の 3 つの価値（取得・補足の提案と追加・データ保存）は機能の並びなので、LP では「どこも言っていないこと」を先頭に出し、3 つの価値はその後ろの流れとして見せる。

### 中心の一言

> ただの画像なのに、何度でも直せる。

「普通の画像に見える形で保存できる」と「何度でも編集できる」の 2 点を、1 文の対比で言う。説明文で「保存はふつうの JPEG / PNG。どこにでも貼れて、Harie で開けば枠も文字も何度でも直せます。」と補う。

- 初案は「貼ったあとも、はがせるスクリーンショット。」（名前の由来の貼り絵にかけた）だったが、意味が伝わりにくいので 2026-10-19 に差し替えた。

### 文体

- 本文は、人が書いたような自然な文で書く。体言止めや「・」での単語の羅列、「〜を。」で終わる言い切りを続けない（2026-10-20 に全体を書き直した）。
- 見出しは短い言い切りでよい。中心の一言は変えない。
- 提供状況のタグは「準備中」のものだけ付ける。使えるものに「今すぐ使える」などのタグは付けない。

### 訴求の柱（優先順）

| # | 柱 | 言い方 | 根拠（要件・ADR） | 参考ツールとの差 |
|---|---|---|---|---|
| 1 | 保存後も直せる | 画像 1 枚に注釈と元画像が入っている。プロジェクトファイルを探さなくていい | FR-FILE-01〜04、NFR-DATA-01、ADR-0004 | 他は独自形式か SaaS 上のデータが前提 |
| 2 | 誰でも直せる | ファイルを受け取った人が、そのまま開いて直せる。前任者の画像も | FR-FILE-03、NFR-DATA-04 | 作成者の手元・契約に縛られない |
| 3 | AI が補足を考える | どこを囲み、何と書くかを AI が提案。採用は 1 クリック | FR-AI-01〜03 | 共通の訴求（時間が減る・品質がそろう）を満たす |
| 4 | AI エージェントから直せる | Claude などに「保存ボタンを赤枠で囲んで」と頼めば MCP 経由で注釈が付く。UI の文言変更もまとめて直せる | FR-MCP-01〜05 | 他にない |
| 5 | 個人情報は伝わる形で消す | 氏名やメールをダミーに置き換える。元に戻せない加工なので、画像を渡しても元の値は残らない | FR-PII-01〜05、ADR-0007 | ぼかしではなく置き換え。復元できない |
| 6 | 撮ってそのまま書ける | Chrome 拡張で表示中のページを撮り、すぐ注釈を付ける | FR-CAP-01〜04 | 共通の訴求（1 本で済む） |
| 7 | どこでも同じ見た目 | Web・Chrome 拡張・デスクトップ・MCP で同じ描画 | NFR-PLAT-05、ADR-0005 | — |
| 8 | 手元で完結・オープンソース | 画像をサーバーに送らない。AI は自分の API キーで使う。MIT ライセンス | NFR-SEC-01、NFR-SEC-04 | SaaS 型は画像を預ける |

### 言わないこと

- 「自動で手順書ができる」: 操作記録からの自動生成はしていない。
- 「ストアからインストール」はデスクトップ版には言わない（配布準備中。LP では「準備中」と書く）。Chrome 拡張は 2026-10-23 に Chrome ウェブストアで公開した。
- 実在の社名・サービス名を使った例。デモ画像は架空の SaaS「Tasklane」で作る。

### 想定読者の課題と見出しの対応

| 課題（要求整理 3 章） | LP の見出し |
|---|---|
| P1 どこをどう補足するか迷う | AI が「どこに・何を」を提案する |
| P2 取得〜補足に時間がかかる | 撮って、そのまま書く |
| P3 UI 変更のたびに作り直し | 文言 1 つなら開いて直すだけ |
| P4 他人が作った画像を直せない | 受け取った画像をそのまま直せる |

LP の課題の節では P3 と P4 を「文言が 1 つ変わるだけで作り直し」の 1 枚にまとめ、4 枚のカードそれぞれに Harie での解き方と該当する節へのリンクを付ける。
| P5 個人情報の映り込み | 何の画面かは伝わるまま、個人情報だけ消す |

## 3. 英語版

日本語版と同じ構成・同じ主張で英語版（`/en/`）を持つ。直訳ではなく、英語で自然な言い方にする。

| 日本語 | 英語 |
|---|---|
| ただの画像なのに、何度でも直せる。 | Just an image. Editable anytime. |
| 撮って、書き込んで、残す。 | Capture it, annotate it, keep it. |
| 1 枚の画像に、元の画面と注釈が入っている。 | One image holds the original screen and the annotations. |
| 何の画面かは伝わるまま、個人情報だけ消す。 | Remove personal data, keep the meaning. |

- エディタの画面は英語と日本語に対応している（NFR-I18N-01）。英語版ではそのことをヒーローの注記と Web の説明に書く（設定で切り替えられる）。
- 見本画像は英語の画面（架空の Tasklane）で作る。

## 4. ページ構成

1. ヒーロー: 中心の一言、デモ画像（注釈を付けた状態とはがした状態を切り替える）、「ブラウザで使う」と「Chrome 拡張を入れる」（ストアへ）。GitHub へのリンクは注記の中に置く。締めの CTA も同じ 2 つ
2. 課題: ガイド画像づくりでよくある 4 つの手間と、それぞれの解き方（2 × 2 のカード）
3. 流れ: 撮る → 書き込む → 残す（3 つの価値）
4. 保存後も直せる仕組み: 画像 1 枚に元画像と注釈が入っている図、一般的な書き出しとの比較
5. AI とエージェント: 提案、MCP で頼む例
6. 個人情報の加工: ダミー置換の例
7. 使える場所: Web / Chrome 拡張 / デスクトップ / MCP と、準備中のものの提供状況
8. MCP の始め方: 説明の直後に登録のしかた（Claude Code / Claude Desktop のタブ。Node.js の版と `--root` は注意書き、その下にツール一覧へのリンク）、続けて頼み方の例
9. 手元で完結・オープンソース
10. 締めの CTA
