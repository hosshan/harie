# 要求整理

- ステータス: ドラフト
- 最終更新: 2026-10-07
- 関連: [要件定義](./requirements-definition.md)

プロダクトの「なぜ・誰のため・何を」を整理する文書。要件（何を作るか）は [要件定義](./requirements-definition.md) に分離する。

## 1. プロダクト概要

**Harie**（はりえ）は、SaaS の利用ガイド・ヘルプ記事に載せるスクリーンショットに、枠・矢印・番号・説明文などの補足を付けるツール。

一般的な画像注釈ツールとの違いは次の 3 点。

1. **保存しても何度でも編集できる。** 出力は普通の JPEG（等）として表示できるが、ファイル内に注釈データと元画像を持つので、後から開くと注釈を個別に動かしたり文言を直したりできる。他人が作った画像でも同じ。
2. **AI から使える。** 補足すべき箇所と文言の提案、個人情報のマスク・ダミー化を AI が行う。MCP 経由で外部の AI エージェントからも注釈を変更できる。
3. **取得から保存まで一続き。** Chrome 拡張で Web サービスの画面をキャプチャし、そのまま注釈を書き込める。

## 2. ターゲット

### 初期ターゲット

SaaS サービスのプロダクトマネージャー（PdM）。ヘルプページ、リリースノート、社内向け操作マニュアル、CS 向け資料を書く立場の人。

### 将来の拡張候補（初期は狙わない）

- カスタマーサクセス、テクニカルライター、マーケター
- QA エンジニア（バグ報告のスクリーンショット）

## 3. ターゲットの課題

| # | 課題 | 現状のやり方と痛み |
|---|---|---|
| P1 | どこをどう補足するか迷う | 何を強調すべきか、どんな文言が伝わるかを毎回考える。人によって品質がばらつく |
| P2 | 画像取得〜補足追加に時間がかかる | キャプチャ → 画像編集ツールで開く → 枠・文字入れ → 書き出し、を画像ごとに繰り返す |
| P3 | UI 変更やガイド改訂のたびに作り直し | 書き出した画像は注釈が焼き込まれており文言 1 つ直すのにも元データが要る。元データ（.psd 等）は所在不明になりがち |
| P4 | 他人が作った画像を直せない | 作成者のローカルにしか編集用データがない。ツールも人によって違う |
| P5 | 個人情報・顧客データの映り込み | 本番に近い画面は実データが映る。ぼかし処理を手作業でやり、漏れが出る。ぼかすと何の画面か伝わりにくい |

## 4. 提供価値

ユーザーの言葉で整理された 3 つの価値に、課題を対応させる。

| 価値 | 内容 | 解決する課題 |
|---|---|---|
| **取得** | Chrome 拡張などで画面をキャプチャし、そのままエディタで開く | P2 |
| **補足の提案と追加** | AI が補足箇所・文言を提案し、ワンクリックで採用。手動編集も可能 | P1, P2 |
| **データ保存** | 通常画像として使えつつ、注釈を後から編集できる形式で保存。個人情報は内容が伝わる形で加工 | P3, P4, P5 |

## 5. ユーザー要求（ユーザーの言葉ベース）

依頼時に挙がった要求をそのまま列挙し、要件定義の ID と対応付ける。

| # | 要求 | 対応する要件 |
|---|---|---|
| R1 | JPEG など、通常の画像として表示できる形式で保存する | FR-FILE-01, 02 |
| R2 | 後から追加した枠や文字は、保存後も変更できるようにする | FR-FILE-03, 04 |
| R3 | 保存ファイル名のイメージ: `example.{anoi:サービス名}.jpeg` | FR-FILE-06（[ADR-0006](../adr/0006-file-naming.md)） |
| R4 | アプリ・Web・デスクトップで使えるようにする | NFR-PLAT-01〜03（[ADR-0002](../adr/0002-app-platform.md)） |
| R5 | Web サービスの画像キャプチャを Chrome 拡張で取得して、そのまま書き込めるようにする | FR-CAP-01〜04 |
| R6 | MCP 経由でもアノテーションを変更できるようにする | FR-MCP-01〜05 |
| R7 | 映っているデータを、内容が伝わり個人情報などがない形に加工できる | FR-PII-01〜05 |
| R8 | AI で利用できる（補足の提案） | FR-AI-01〜03 |

## 6. 利用シナリオ

### S1: 新機能のヘルプ記事を書く（主シナリオ）

1. PdM が自社 SaaS の新機能画面を開き、Chrome 拡張でキャプチャする。
2. 拡張が DOM 情報（要素の位置・テキスト）と一緒にエディタへ渡す。
3. 「この画面で〇〇の設定方法を説明したい」と入力すると、AI が番号付きの枠と説明文を提案する。
4. 個人情報らしき文字列（メール・氏名・電話番号）がハイライトされ、ダミー値への置換を提案される。
5. 提案を採用・微調整して `settings.harie.jpg` として保存し、ヘルプ CMS にそのままアップロードする。

### S2: UI 変更に合わせてガイドを更新する

1. ボタン文言が変わったため、既存の `settings.harie.jpg` をエディタで開く。
2. 注釈は編集可能な状態で復元される。説明文だけ書き換えて上書き保存。
3. 画面自体が変わった場合は、新しいキャプチャに差し替え、既存の注釈を引き継いで位置を調整する。

### S3: 他の人が作ったガイド画像を直す

1. 前任者が作った画像を共有ドライブから取得し、エディタで開く（作成者のローカル環境は不要）。
2. 注釈を修正して保存。

### S4: AI エージェントからまとめて更新する

1. 開発者や PdM が Claude などの MCP クライアントに「docs/images 以下のガイド画像で『保存』ボタンの説明を『登録』に変えて」と依頼する。
2. エージェントが Harie MCP サーバー経由で各画像の注釈を読み、該当テキストを書き換え、再レンダリングして保存する。

## 7. 成功指標（仮）

MVP の検証で見る指標。数値目標はユーザー検証の前に決める。

- 1 枚あたりの「キャプチャ → 注釈付き画像の保存」所要時間（現状比）
- AI 提案の採用率（提案された注釈のうち、そのまま／微修正で採用された割合）
- 保存後に再編集されたファイルの割合（R2 の価値が使われているか）
- 個人情報の検出漏れ件数（検証用データセットで計測）

## 8. スコープ外（当面やらないこと）

- 動画・GIF への注釈
- 高度な画像編集（レイヤー合成、フィルタ、写真加工）
- ガイド記事そのものの執筆・CMS 機能
- リアルタイム共同編集
