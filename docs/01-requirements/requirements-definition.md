- ステータス: ドラフト
- 最終更新: 2026-10-07

## 0. この文書の使い方

- 要件には ID を振る（`FR-<領域>-<番号>` / `NFR-<領域>-<番号>`）。PR・テスト・Issue からはこの ID で参照する。
- **優先度**: `MVP`（最初のリリースに必須）/ `Next`（MVP 直後）/ `Later`（検証結果次第）。
- ID は削除せず、不要になったら「廃止」と書いて残す（履歴の追跡のため）。

## 1. 用語

[用語集](../glossary.md) を参照。主要な用語のみ再掲する。

| 用語 | 意味 |
|---|---|
| Harie ファイル | 注釈データと元画像を埋め込んだ画像ファイル。見た目は通常の JPEG / PNG |
| ベース画像 | 注釈を焼き込む前の画像（マスク処理済み）。再編集時の下地 |
| レンダリング画像 | ベース画像に注釈を焼き込んだ画像。Harie ファイルのピクセルそのもの |
| 注釈ドキュメント | 注釈（枠・矢印・テキストなど）の構造化データ（JSON） |

## 2. 機能要件

### 2.1 ファイル形式・保存（FILE）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-FILE-01 | 注釈を焼き込んだ画像を JPEG として保存できる。保存したファイルは一般的なビューア・ブラウザ・CMS で通常の画像として表示できる | MVP |
| FR-FILE-02 | PNG でも保存できる（文字が多い画面向け）。保存時に JPEG / PNG を選べる（既定は開いたファイルの形式） | MVP |
| FR-FILE-03 | 保存ファイルに注釈ドキュメントとベース画像を埋め込み、Harie で開くと全注釈を編集可能な状態で復元できる | MVP |
| FR-FILE-04 | 保存・再編集を何度繰り返しても、ベース画像の画質が劣化しない（再エンコードしない） | MVP |
| FR-FILE-05 | 外部ツールで再エンコード・リサイズされ埋め込みデータが失われた／不整合になったファイルを検出し、ユーザーに伝える | MVP |
| FR-FILE-06 | ファイル名を規則に従って自動生成する（[ADR-0006](../adr/0006-file-naming.md)） | MVP |
| FR-FILE-07 | 埋め込みデータのフォーマットバージョンを持ち、古いバージョンのファイルを読める（後方互換） | MVP |
| FR-FILE-08 | 通常の画像（Harie ファイルでない JPEG/PNG）を開いて新規ドキュメントにできる | MVP |
| FR-FILE-09 | WebP で保存できる | Later |
| FR-FILE-10 | 埋め込みデータが失われたファイルを、クラウド上の控え（docId 照合）から復元できる | Later |
| FR-FILE-11 | ファイルに保存せず、注釈を描いた今の画像を PNG としてクリップボードにコピーできる（チャットや文書にそのまま貼り付ける用。注釈データは載らない） | Next |
| FR-FILE-12 | Chrome 拡張を入れていると、ウェブページ（GitHub のファイル表示・差分を含む）上の Harie 画像で、説明文（吹き出し・文字）の枠にカーソルを当てるとその枠の上にコピーボタンを出し、その説明文をコピーできる。画像の右上の「まとめてコピー」で、番号順の説明文を一度にコピーできる。カーソルを当てるまでページの見た目は変えない。利用者がオンにしたときだけ動く | Next |
| FR-FILE-13 | Chrome 拡張を入れていると、ウェブページ上の Harie 画像（ファイル名が規則どおり、または注釈データが埋め込まれている画像）にカーソルを当てたとき、右上に薄く編集ボタンを出し、押すと拡張のエディタで開いて直せる（保存はダウンロード）。利用者がオンにしたときだけ動く | Next |
| FR-FILE-14 | Web エディタをアプリとしてインストールしていると、OS の「このアプリで開く」で画像（JPEG / PNG と FR-FILE-15 の形式）を Harie で開ける。開いた Harie ファイルは、保存でそのファイルに上書きできる（ブラウザが File Handling API に対応しているとき） | Next |
| FR-FILE-15 | JPEG / PNG 以外の画像（SVG・WebP・GIF・BMP・AVIF・HEIC）も開いて注釈を付けられる。開くとき・画像を差し替えるときに一度だけ PNG（HEIC・AVIF は JPEG）に変換してベース画像にし、保存形式は JPEG / PNG のまま。MCP・CLI・Skill は SVG・WebP・GIF・HEIC（[ADR-0016](../adr/0016-import-other-image-formats.md)） | Next |

### 2.2 注釈編集（EDIT）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-EDIT-01 | 矩形枠（角丸、線色、線幅、線の種類（実線・破線・点線））を追加・移動・リサイズ・削除できる。楕円・矢印も線幅と線の種類を変えられる | MVP |
| FR-EDIT-02 | 矢印を追加・編集できる | MVP |
| FR-EDIT-03 | テキスト（吹き出し・ラベル）を追加・編集できる。日本語を正しく表示する | MVP |
| FR-EDIT-04 | 番号バッジ（①②③）を追加でき、番号は自動で振り直せる | MVP |
| FR-EDIT-05 | 範囲を指定してマスク（塗りつぶし・モザイク・ぼかし）できる | MVP |
| FR-EDIT-06 | ハイライト（範囲外を暗くするスポットライト）を追加できる | Next |
| FR-EDIT-07 | 元に戻す／やり直す | MVP |
| FR-EDIT-08 | スタイルのプリセット（色・フォント・線幅）を保存し、チームで揃えられる | Next |
| FR-EDIT-09 | トリミング（表示範囲の変更）。ベース画像は保持したまま切り抜き範囲だけ記録する | Next |
| FR-EDIT-10 | ベース画像を新しいキャプチャに差し替え、既存の注釈を引き継ぐ | Next |
| FR-EDIT-11 | 注釈を複数選び、まとめて移動・拡大縮小・削除し、共通する項目（色・線の太さ・線の種類・文字サイズ）をまとめて変えられる | Next |
| FR-EDIT-12 | 基本の操作（保存・開く・画像の差し替え・画像のコピー・元に戻す・複製・コピー / 貼り付け・削除・移動・枠の大きさ・重なりの順・道具の切り替え）をキーボードのショートカットで行える。Mac は ⌘、Windows は Ctrl を使い、ショートカットの一覧を見られる。Alt（Mac は Option）を押しながら注釈をドラッグすると、複製して動かせる | Next |
| FR-EDIT-13 | 指やマウス・ペンでなぞった線から、近い図形（四角・楕円・線・矢印）を描ける。描いた図形はほかの注釈と同じように編集でき、どの図形にも近くなければ何も追加しない | Next |
| FR-EDIT-14 | 番号・吹き出しが付いていない枠（四角・楕円）に、AI を使わずまとめて番号（描いた順）と、枠を指す吹き出しを付けられる | Next |
| FR-EDIT-15 | Chrome 拡張でキャプチャした画像では、ページの要素（ボタン・入力欄・リンクなど）をクリックするだけで、その要素にぴったりの枠と、枠に紐付けた番号・要素の名前から作った説明文の吹き出しを付けられる。AI は使わず、何も送信しない | Next |
| FR-EDIT-16 | 新しく描く注釈の線の太さ・文字サイズの既定値と、太さ・大きさの候補を、読み込んだ画像の解像度（Retina で撮った画像など）に合わせる。保存済みの注釈の見た目は変えない | Next |
| FR-EDIT-17 | 枠・線・文字・番号の色を、用意された色のほかにカラーピッカーやカラーコードで作って指定できる。作った色はパレットとしてブラウザに残り、別の画像を編集するときも使え、要らなくなったら外せる | Next |
| FR-EDIT-18 | 画像を開いたとき、注釈のない画像ならなぞるだけで枠・丸・矢印を描けるよう道具をスケッチにし、注釈のある画像なら選択にする。四角・楕円・矢印・番号は描いた後も道具を選択に戻さず、続けて描ける。四角・楕円・矢印の道具でドラッグせずにクリックしたときは描かず、クリックした注釈を選ぶ | Next |
| FR-EDIT-19 | 矢印の始端・終端それぞれに矢じりを付けるかを選べ、矢じりのない線・逆向きの矢印・両矢印を描ける。選んだ矢じりは次に描く矢印に引き継ぐ | Next |
| FR-EDIT-20 | 選んだ注釈を左・左右中央・右・上・上下中央・下に揃え、3 つ以上なら左右・上下に等間隔に並べられる。1 つだけ選んでいるときは画像に対して揃える | Next |
| FR-EDIT-21 | 四角・楕円・テキスト・吹き出しを、選択枠の上の回転のつまみをドラッグして回せる。Shift を押すと 15° 刻みにし、押さなくても 0°・90° などの近くでは吸い付く。回した角度は保存後も再編集できる | Next |
| FR-EDIT-22 | 選んだ注釈を右の欄のボタンで左右に 90° 回転し、左右・上下に反転できる。2 つ以上選んでいれば選んだ全体の中心を軸に位置も回す・入れ替える。文字そのものは鏡に映さない | Next |
| FR-EDIT-23 | 注釈を動かす・描く・大きさを変えるとき、ほかの注釈や画像の端・中央にそろうよう吸着し、そろった線をガイド線で示す。矢印の端は図形の中央や辺の中点に吸い付く。キーを押している間は吸着しない | Next |
| FR-EDIT-24 | 保存・コピーする画像の大きさを幅か高さ（px）の数値で決められる（縦横比は保つ）。ベース画像と注釈はそのまま残し、保存する画像だけをその大きさで描くので、あとから何度でも変えて元の大きさに戻せる（ADR-0018） | Next |

## 3. 非機能要件

| ID | 要件 | 優先度 |
|---|---|---|
| NFR-PLAT-01 | Web ブラウザ（Chrome / Edge / Safari / Firefox の最新版）で動く | MVP |
| NFR-PLAT-02 | Chrome 拡張（Manifest V3） | MVP |
| NFR-PLAT-03 | デスクトップアプリ（macOS / Windows） | Next |
| NFR-PLAT-04 | モバイルアプリ（iOS / Android）で閲覧・簡易編集 | Later |
| NFR-PLAT-05 | すべてのプラットフォームで同じ注釈ドキュメントから同じピクセルが出る（レンダリングの一致） | MVP |
| NFR-PLAT-06 | Web エディタをアプリとしてインストールできる（PWA。ブラウザを開かずに起動し、オフラインでも使える）。ブラウザがインストールを勧められるときは、「連携」の案内からインストールできる | Next |

### 3.2 互換性・データ保全（DATA）

| ID | 要件 |
|---|---|
| NFR-DATA-01 | Harie ファイルは、Harie 以外のツールで開いても通常の画像として表示できる（埋め込みデータは無視されるだけ） |
| NFR-DATA-02 | ファイル形式の仕様は文書化し、バージョンを付ける（[ファイル形式仕様](../03-design/harie-format-spec.md)） |
| NFR-DATA-03 | 破損・不正な埋め込みデータを読んでもクラッシュせず、通常の画像として開く |
| NFR-DATA-04 | ファイルが唯一の正（source of truth）。サーバーがなくても全データが復元できる |

### 3.3 セキュリティ・プライバシー（SEC）

| ID | 要件 |
|---|---|
| NFR-SEC-01 | 画像は既定でローカル処理。AI 機能を使うときだけ外部送信し、送信前にその旨を表示する |
| NFR-SEC-02 | PII 加工後のファイルに加工前のピクセル・テキストが残らないことをテストで保証する |
| NFR-SEC-03 | Chrome 拡張の権限は最小限（`activeTab` 中心。`<all_urls>` 常時権限は取らない。ページ上の Harie 画像（FR-FILE-12, 13）のためのサイト権限は、利用者がオンにしたときだけ求める任意の権限にする） |
| NFR-SEC-04 | API キーなどの秘密情報をリポジトリ・ファイル・ログに残さない |
| NFR-SEC-05 | 埋め込みデータに作成者の個人情報（氏名・メール）を既定では含めない |

### 3.4 性能（PERF）

| ID | 要件（目安） |
|---|---|
| NFR-PERF-01 | 2560×1600 の画像で、保存（レンダリング＋エンコード＋埋め込み）が 2 秒以内 |
| NFR-PERF-02 | 注釈の移動・リサイズが 60fps 相当で追従する |
| NFR-PERF-03 | Harie ファイルのサイズは、同じ画像の通常 JPEG の 2.5 倍以内（ベース画像を同梱するため約 2 倍になる） |

### 3.5 アクセシビリティ・国際化（I18N）

| ID | 要件 |
|---|---|
| NFR-I18N-01 | UI は日本語・英語・韓国語・繁體中文・简体中文・スペイン語・ポルトガル語（ブラジル）。注釈テキストは CJK を含む任意の Unicode を表示できる（ハングル・簡体字は補助フォント、ADR-0013） |
| NFR-I18N-02 | 注釈テキストを画像の代替テキスト（alt）候補として書き出せる（Next） |

## 4. MVP の範囲

| 含む | 含まない |
|---|---|
| Web アプリ（PWA）、Chrome 拡張、ローカル MCP サーバー | デスクトップアプリ（Next）、モバイル（Later） |
| JPEG / PNG の読み書き（埋め込み・再編集） | WebP、クラウド保存・同期 |
| 矩形・矢印・テキスト・番号・マスク | スポットライト、プリセット共有、トリミング |
| AI 補足提案、PII 検出とダミー置換 | 文体の書き直し、DOM 置換キャプチャ |

MVP で「取得 → 提案 → 保存 → 再編集 → MCP から更新」の一連が通ることを最優先とする。
