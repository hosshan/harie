# ADR-0014: 矢印の矢じりを始端・終端それぞれに付け外しできるよう、`style.head` に `start` を加える

- ステータス: 承認
- 日付: 2026-11-11
- 決定者: Shun（2026-11-11 に「矢印の始端と終端をそれぞれ設定できるように」と依頼。この ADR を含む PR のマージで承認）
- 関連: FR-EDIT-02 / FR-EDIT-19 / [注釈ドキュメントモデル](../03-design/document-model.md) / [ADR-0004](./0004-image-container-format.md)

## 背景

矢印ではなく、矢じりのないただの線を描きたいという要望がある。矢印（`type: "arrow"`）は `style.head` に `end`（終端 = `to` 側だけ。省略時）/ `both` / `none` を持てるが、エディタの右の欄から変える手段がなく、`none` はスケッチで線を描いたときにしか付かない。また、始端（`from` 側）だけに矢じりを付ける値がない。

始端・終端をそれぞれ「なし / 矢印」から選べるようにすると、4 通りの組み合わせを表せる必要がある。注釈ドキュメントは保存した画像に埋め込まれ、古い版のアプリ（ストア公開済みの Chrome 拡張、npm の @harie/mcp など）でも開かれる。

## 選択肢

### A. `style.head` の値に `start` を加える（`end` / `start` / `both` / `none`）

- 長所: 1 つのフィールドで 4 通りを表せ、MCP や AI からも読み書きしやすい。既存のファイルはそのまま読める。描画の変更は始端側の矢じりを描く条件だけ。
- 短所: `head: "start"` を含むファイルは、古い版では検証に通らず「注釈データを読めません。画像だけを開きました。」になる（画像の表示はできる。新しい版では問題なく開ける）。

### B. 新しいフィールド（例: `startHead` / `endHead`）を足し、`head` は互換用に残す

- 長所: 古い版でも注釈を読める（未知のフィールドは保持して無視する）。
- 短所: 同じことを 2 つのフィールドで持ち、食い違ったときの決まりが要る。古い版では始端だけの矢印が別の形（終端の矢印）で描かれ、見た目が黙って変わる。

### C. 形式は変えず、始端だけのときは `from` と `to` を入れ替えて `head: "end"` で保存する

- 長所: 形式を変えない。
- 短所: 保存した時点で始端と終端が入れ替わり、右の欄で「始端だけ」を選ぶと表示が「終端だけ」に変わってしまう。利用者に始端・終端を選ばせる UI と両立しない。

## 決定

A を採る。値が 1 つ増えるだけで意味が素直で、エディタ・MCP・CLI が同じ値を共有できる。古い版で開けなくなるのは始端だけの矢印を使ったファイルに限られ、画像としては表示できる。B は古い版で見た目が黙って変わる方が問題が大きく、C は UI と両立しない。

- `start` は `from` 側、`end` は `to` 側。省略は従来どおり `end`（既存のファイルの見た目は変わらない）。
- 矢じりの付け外しの判定と値の組み立ては `arrowEnds` / `arrowHeadOf`（`packages/model`）にまとめ、描画とエディタで共有する。
- `schemaVersion` は上げない（既存のファイルはそのまま読め、変換も要らない）。

## 結果（影響）

- 良くなること: 右の欄で始端・終端の矢じりをそれぞれ付け外しでき、ただの線・逆向きの矢印・両矢印を描ける。MCP・CLI も同じ `style.head` で指定できる。
- 悪くなること・受け入れるコスト: `head: "start"` を含むファイルは、この変更より前の版では注釈を読めない（画像だけを開く）。
- 後でやること / 再評価の条件: 矢じりの種類（丸・ひし形など）を足すときは、同じ問題が起きないよう、知らない値を既定に読み替えて保持する読み込み方を検討する。
