# 要件定義

- ステータス: ドラフト
- 最終更新: 2026-10-07
- 関連: [要求整理](./requirements-analysis.md) / [アーキテクチャ](../03-design/architecture.md) / [実装計画](../04-plan/implementation-plan.md)

## 0. この文書の使い方

- 要件には ID を振る（`FR-<領域>-<番号>` / `NFR-<領域>-<番号>`）。PR・テスト・Issue からはこの ID で参照する。
- **優先度**: `MVP`（最初のリリースに必須）/ `Next`（MVP 直後）/ `Later`（検証結果次第）。
- ID は削除せず、不要になったら「廃止」と書いて残す（履歴の追跡のため）。

## 1. 用語

[用語集](../glossary.md) を参照。主要な用語のみ再掲する。

| 用語 | 意味 |
|---|---|
| Anoi ファイル | 注釈データと元画像を埋め込んだ画像ファイル。見た目は通常の JPEG / PNG |
| ベース画像 | 注釈を焼き込む前の画像（マスク処理済み）。再編集時の下地 |
| レンダリング画像 | ベース画像に注釈を焼き込んだ画像。Anoi ファイルのピクセルそのもの |
| 注釈ドキュメント | 注釈（枠・矢印・テキストなど）の構造化データ（JSON） |

## 2. 機能要件

### 2.1 ファイル形式・保存（FILE）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-FILE-01 | 注釈を焼き込んだ画像を JPEG として保存できる。保存したファイルは一般的なビューア・ブラウザ・CMS で通常の画像として表示できる | MVP |
| FR-FILE-02 | PNG でも保存できる（文字が多い画面向け） | MVP |
| FR-FILE-03 | 保存ファイルに注釈ドキュメントとベース画像を埋め込み、Anoi で開くと全注釈を編集可能な状態で復元できる | MVP |
| FR-FILE-04 | 保存・再編集を何度繰り返しても、ベース画像の画質が劣化しない（再エンコードしない） | MVP |
| FR-FILE-05 | 外部ツールで再エンコード・リサイズされ埋め込みデータが失われた／不整合になったファイルを検出し、ユーザーに伝える | MVP |
| FR-FILE-06 | ファイル名を規則に従って自動生成する（[ADR-0006](../adr/0006-file-naming.md)） | MVP |
| FR-FILE-07 | 埋め込みデータのフォーマットバージョンを持ち、古いバージョンのファイルを読める（後方互換） | MVP |
| FR-FILE-08 | 通常の画像（Anoi ファイルでない JPEG/PNG）を開いて新規ドキュメントにできる | MVP |
| FR-FILE-09 | WebP で保存できる | Later |
| FR-FILE-10 | 埋め込みデータが失われたファイルを、クラウド上の控え（docId 照合）から復元できる | Later |

### 2.2 注釈編集（EDIT）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-EDIT-01 | 矩形枠（角丸、線色、線幅）を追加・移動・リサイズ・削除できる | MVP |
| FR-EDIT-02 | 矢印を追加・編集できる | MVP |
| FR-EDIT-03 | テキスト（吹き出し・ラベル）を追加・編集できる。日本語を正しく表示する | MVP |
| FR-EDIT-04 | 番号バッジ（①②③）を追加でき、番号は自動で振り直せる | MVP |
| FR-EDIT-05 | 範囲を指定してマスク（塗りつぶし・モザイク・ぼかし）できる | MVP |
| FR-EDIT-06 | ハイライト（範囲外を暗くするスポットライト）を追加できる | Next |
| FR-EDIT-07 | 元に戻す／やり直す | MVP |
| FR-EDIT-08 | スタイルのプリセット（色・フォント・線幅）を保存し、チームで揃えられる | Next |
| FR-EDIT-09 | トリミング（表示範囲の変更）。ベース画像は保持したまま切り抜き範囲だけ記録する | Next |
| FR-EDIT-10 | ベース画像を新しいキャプチャに差し替え、既存の注釈を引き継ぐ | Next |

### 2.3 キャプチャ（CAP）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-CAP-01 | Chrome 拡張で、表示中タブの可視範囲をキャプチャし、そのままエディタで開ける | MVP |
| FR-CAP-02 | 要素選択・範囲選択でキャプチャできる | MVP |
| FR-CAP-03 | キャプチャ時に DOM 情報（主要要素の位置・ラベル・テキスト）を取得し、AI 提案と個人情報検出に使う | MVP |
| FR-CAP-04 | ページ全体（スクロール範囲を含む）をキャプチャできる | Next |
| FR-CAP-05 | クリップボード・ファイルのドラッグ＆ドロップから画像を取り込める | MVP |
| FR-CAP-06 | デスクトップアプリから画面・ウィンドウをキャプチャできる | Later |

### 2.4 AI 補足提案（AI）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-AI-01 | 画像と「何を説明したいか」を入力すると、補足すべき箇所（位置）と説明文を提案する | MVP |
| FR-AI-02 | 提案は注釈として下書き表示し、個別に採用・却下・修正できる | MVP |
| FR-AI-03 | DOM 情報がある場合は要素の実座標に枠を合わせる（画像認識だけに頼らない） | MVP |
| FR-AI-04 | 既存の注釈文言を、指定した文体・用語集に合わせて書き直す | Next |

### 2.5 個人情報の加工（PII）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-PII-01 | 画像内の個人情報らしき文字列（氏名・メール・電話番号・住所・顔など）を検出し、候補として示す | MVP |
| FR-PII-02 | 検出箇所を「ダミー値への置換」で加工できる（例: 山田太郎 → 佐藤花子）。画面の意味が伝わる形を既定とする | MVP |
| FR-PII-03 | ぼかし・モザイク・塗りつぶしも選べる | MVP |
| FR-PII-04 | 加工はベース画像に対して不可逆に適用し、埋め込みデータに加工前の情報を残さない | MVP |
| FR-PII-05 | Chrome 拡張では、キャプチャ前に DOM 上のテキストをダミー値に置き換えてから撮影できる（文字の自然さが最も高い） | Next |

### 2.6 MCP（MCP）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-MCP-01 | ローカルで動く MCP サーバーを提供する（stdio） | MVP |
| FR-MCP-02 | 指定パスの Anoi ファイルを開き、注釈一覧と画像を返せる | MVP |
| FR-MCP-03 | 注釈の追加・更新・削除ができ、保存時に再レンダリングされる | MVP |
| FR-MCP-04 | 通常の画像から新規 Anoi ファイルを作れる | MVP |
| FR-MCP-05 | 複数ファイルを横断して注釈テキストを検索できる | Next |
| FR-MCP-06 | リモート MCP（Streamable HTTP + OAuth）でクラウド上のファイルを扱える | Later |

## 3. 非機能要件

### 3.1 プラットフォーム（PLAT）

| ID | 要件 | 優先度 |
|---|---|---|
| NFR-PLAT-01 | Web ブラウザ（Chrome / Edge / Safari / Firefox の最新版）で動く | MVP |
| NFR-PLAT-02 | Chrome 拡張（Manifest V3） | MVP |
| NFR-PLAT-03 | デスクトップアプリ（macOS / Windows） | Next |
| NFR-PLAT-04 | モバイルアプリ（iOS / Android）で閲覧・簡易編集 | Later |
| NFR-PLAT-05 | すべてのプラットフォームで同じ注釈ドキュメントから同じピクセルが出る（レンダリングの一致） | MVP |

### 3.2 互換性・データ保全（DATA）

| ID | 要件 |
|---|---|
| NFR-DATA-01 | Anoi ファイルは、Anoi 以外のツールで開いても通常の画像として表示できる（埋め込みデータは無視されるだけ） |
| NFR-DATA-02 | ファイル形式の仕様は文書化し、バージョンを付ける（[ファイル形式仕様](../03-design/anoi-format-spec.md)） |
| NFR-DATA-03 | 破損・不正な埋め込みデータを読んでもクラッシュせず、通常の画像として開く |
| NFR-DATA-04 | ファイルが唯一の正（source of truth）。サーバーがなくても全データが復元できる |

### 3.3 セキュリティ・プライバシー（SEC）

| ID | 要件 |
|---|---|
| NFR-SEC-01 | 画像は既定でローカル処理。AI 機能を使うときだけ外部送信し、送信前にその旨を表示する |
| NFR-SEC-02 | PII 加工後のファイルに加工前のピクセル・テキストが残らないことをテストで保証する |
| NFR-SEC-03 | Chrome 拡張の権限は最小限（`activeTab` 中心。`<all_urls>` 常時権限は取らない） |
| NFR-SEC-04 | API キーなどの秘密情報をリポジトリ・ファイル・ログに残さない |
| NFR-SEC-05 | 埋め込みデータに作成者の個人情報（氏名・メール）を既定では含めない |

### 3.4 性能（PERF）

| ID | 要件（目安） |
|---|---|
| NFR-PERF-01 | 2560×1600 の画像で、保存（レンダリング＋エンコード＋埋め込み）が 2 秒以内 |
| NFR-PERF-02 | 注釈の移動・リサイズが 60fps 相当で追従する |
| NFR-PERF-03 | Anoi ファイルのサイズは、同じ画像の通常 JPEG の 2.5 倍以内（ベース画像を同梱するため約 2 倍になる） |

### 3.5 アクセシビリティ・国際化（I18N）

| ID | 要件 |
|---|---|
| NFR-I18N-01 | UI は日本語・英語。注釈テキストは CJK を含む任意の Unicode を表示できる |
| NFR-I18N-02 | 注釈テキストを画像の代替テキスト（alt）候補として書き出せる（Next） |

## 4. MVP の範囲

| 含む | 含まない |
|---|---|
| Web アプリ（PWA）、Chrome 拡張、ローカル MCP サーバー | デスクトップアプリ（Next）、モバイル（Later） |
| JPEG / PNG の読み書き（埋め込み・再編集） | WebP、クラウド保存・同期 |
| 矩形・矢印・テキスト・番号・マスク | スポットライト、プリセット共有、トリミング |
| AI 補足提案、PII 検出とダミー置換 | 文体の書き直し、DOM 置換キャプチャ |

MVP で「取得 → 提案 → 保存 → 再編集 → MCP から更新」の一連が通ることを最優先とする。
