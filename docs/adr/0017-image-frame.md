# ADR-0017: 保存する画像の仕上げ（余白・影・枠線）を注釈ドキュメントの `frame` に持ち、描画時に画像の外側へ描く

- ステータス: 承認
- 日付: 2026-11-13
- 決定者: Shun（2026-11-13 に「キャプチャ画像に影や背景を付けたい」と依頼。この ADR を含む PR のマージで承認）
- 関連: FR-FILE-16 / [注釈ドキュメントモデル](../03-design/document-model.md) / [ADR-0004](./0004-image-container-format.md) / [ADR-0005](./0005-rendering-pipeline.md) / [ADR-0015](./0015-annotation-rotation.md)

## 背景

白い背景のヘルプページに画面キャプチャを貼ると、画像の白い部分とページの境目が分からない。画像のまわりに影・余白・枠線を付けたいという要望がある。

Harie の保存ファイルは「注釈を焼き込んだ画像」＋「埋め込んだベース画像と注釈ドキュメント」で、ベース画像は再エンコードしない（ADR-0004）。描画は `packages/render` の 1 系統だけ（ADR-0005）。仕上げも保存後に変えたり外したりできる必要がある。

## 選択肢

### A. ドキュメントに任意のフィールド `frame` を足し、描画時に画像の外側を広げて描く

- 長所: ベース画像はそのまま（ADR-0004）。保存後も選び直せ、外せば元の大きさに戻る。注釈の座標は画像のピクセルのままで、既存の注釈・MCP の座標の意味が変わらない。描画は `buildSvg` が画像の SVG を外側の SVG で包むだけで、Web・拡張・デスクトップ・MCP で同じ結果になる（ADR-0005）。
- 短所: 保存した画像の大きさがベース画像（`canvas`）より余白の分だけ大きくなる。保存した画像の上に注釈の位置を重ねる処理（Chrome 拡張のページ上のコピー、FR-FILE-12）は余白を考える必要がある。古い版はフィールドを残すが、仕上げなしで描く。

### B. 仕上げを注釈（`type: "frame"`）として持つ

- 短所: 注釈は画像の座標の中に描くもので、画像の外側を広げる意味と合わない。古い版では知らない種類の注釈になり、ファイルごと読めなくなる。

### C. 保存するときの書き出し設定（エディタの設定）にし、ドキュメントに持たない

- 長所: ドキュメントの形が変わらない。
- 短所: 開き直すと仕上げが分からず、別の人・MCP が保存すると仕上げが消える。「保存後も何度でも直せる」という Harie の約束に合わない。

## 決定

A を採る。

- `frame`（任意）: `padding`（余白 px）、`background`（`#RRGGBB` か `transparent`。省略は白）、`radius`（画像の角の丸み px）、`border`（`{ width, color? }`。画像の縁の内側に引く）、`shadow`（`{ blur, y?, color? }`。CSS の box-shadow の blur と同じ感覚の値。`y` の省略は blur の 1/4、色の省略は黒の 25%）。値は画像のピクセル。
- 余白・角丸・線・影がどれもない `frame` は、ないのと同じに扱う。
- `transparent` は PNG で保存したときだけ透過にする。JPEG は透過できないので白にする。画像の部分は透過の PNG をベースにしても、これまでどおり白地に描く。
- `buildSvg` は保存用（`applyOutputSize: true`）のときだけ包む。書き出しの大きさ（`canvas.output`、[ADR-0018](./0018-output-size.md)）を決めているときは、画像をその大きさで描き、仕上げの値も同じ倍率で縮めて外側に付ける（保存する画像の幅は `output.width + 2 × padding × 倍率`）。エディタの編集面は注釈の座標と画面を合わせるため包まず、`buildFramePreview` の SVG を編集面の外側へはみ出して重ねて見せる。`renderer.render` は既定で包み（保存・コピー）、`atOutputSize: false` で大きさも仕上げも反映しない。
- MCP は `harie_edit` の操作 `{"op":"frame","frame":...}`（`null` で外す）で指定する。AI に返す画像は注釈の座標と合わせるため仕上げなし・ベース画像の大きさで描く。
- エディタは何も選んでいないときの右の欄に「画像の仕上げ」として 枠線・影・角丸 の 3 つの切り替えだけを置き、それぞれ付け外しして組み合わせられる（2026-11-14 に Shun の提案で、なし・枠線・影・影と角丸 の 4 択から変更）。値は画像の解像度（FR-EDIT-16）に合わせて大きくする。選ぶ手間を増やさないよう余白の色は選ばせず、影の余白は透明にする（PNG では透過、JPEG では白。Shun の判断）。影を付けたとき余白がなければ透明の余白を足し、影を外すと透明の余白も外す。AI・MCP で付けた独自の値は、切り替えた部品のほかはそのまま残す。
- エディタの編集面は、仕上げがないときも画像の端が分かるよう台の上に影を付けて見せるが、縁の線は付けない（仕上げの「枠線」と見分けがつかなくなるため）。
- `schemaVersion` は上げない。

## 結果（影響）

- 良くなること: 白いページに貼っても画像の境目が分かる。仕上げは保存後も選び直せ、MCP・Skill からも付けられる。
- 悪くなること・受け入れるコスト: 仕上げを付けると保存した画像がベース画像より大きい（余白の分）。@harie/mcp 0.9.0 より前の版・この変更より前のアプリでは、仕上げを残したまま仕上げなしで描く。MCP のツール定義が少し大きくなる。
- 後でやること / 再評価の条件: 余白の大きさや影の濃さを細かく変えたい要望が出たら、右の欄に数値の入力を足す。画像の差し替え（FR-EDIT-10）で大きさが大きく変わる場合に仕上げの値を合わせるかは、要望が出たら検討する。
